# Old Mirror — Project Instructions

## General Rules

- Inspect existing code before proposing changes.
- Never assume files, functions or components exist.
- Preserve existing architecture and functionality.
- Avoid unnecessary refactoring.
- Do not modify unrelated files.
- Explain the root cause before fixing bugs.
- Verify changes before reporting completion.

## Development Workflow

1. Understand the request.
2. Inspect relevant source files.
3. Identify affected components.
4. Prepare an implementation plan.
5. Wait for approval when requested.
6. Implement the smallest viable change.
7. Run relevant tests.
8. Report changed files and verification results.

## Project Knowledge

The project architecture is not yet documented.

First inspect the repository and identify:
- Backend technologies
- Frontend technologies
- Application entry points
- API endpoints
- Video streaming implementation
- Configuration and environment variables
- Startup procedures

Do not invent architecture details.

## Safety

- Never expose secrets or credentials.
- Never overwrite environment configuration without approval.
- Never delete project files without approval.
- Never claim successful testing without actual verification.
